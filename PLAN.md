# План: влияние функции награды на дообучение Qwen3 в задаче Countdown

План записан до основных прогонов, бюджет после пилота - в разделе 6.

## 1. Постановка

Вопрос. Проверяем, помогает ли частичная награда информацией о близости к цели или достаточно создать разброс наград в группах, где все ответы неверны.

Механизм. При бинарной награде группа из 8 неверных ответов даёт нулевой advantage - сигнал о том, насколько ответ лучше среднего по группе. Частичная награда может создать разброс. Нормировка по стандартному отклонению группы (`scale_rewards="group"` по умолчанию в trl) увеличивает даже малые различия до advantage порядка плюс-минус 1. Частичная награда даёт информацию о близости, бонус за верный набор чисел и сигнал в группах с нулевыми бинарными наградами. Контроль с перестановкой проверяет роль информации.

Условия (модель, данные, промпт, гиперпараметры, бюджет и оценка одинаковы):

| | Награда | seed |
|---|---|---|
| A (исходная награда задания) | 1 за строго верный ответ, иначе 0 | 0-4 |
| C-shuf (контроль) | как C, но внутри группы оценки переставлены случайно между всеми ответами «числа верные, значение неверное», включая получившие 0 | 0-7 |
| C (эксперимент) | 1 за строго верный; при верном мультимножестве и неверном значении `0.5 * max(0, 1 - \|v-t\|/t)`; иначе 0 | 0-7 |
| B (лазейка, иллюстрация) | как C, но допустимость чисел проверяется по принадлежности исходному множеству; точное значение даёт 1 | 0 |

C и C-shuf сохраняют те же награды в одной и той же группе ответов, бонус за числа и нормировку. Перестановка меняет связь оценки с близостью. Число seed зафиксировано заранее: C и C-shuf по 8 для основного сравнения, A для вторичных сравнений, B для иллюстрации лазейки.

Гипотеза. C лучше C-shuf: информация о близости направляет модель к выражениям нужного порядка величины, а перестановка превращает этот сигнал в шум. Конкурирующее объяснение: числовая близость слабо помогает искать выражение, а эффект держится на оживлении групп и бонусе за числа. Тогда C и C-shuf дадут близкую точность.

Основная метрика и правило решения.

- Метрика: строгая точность на test (2000 задач, greedy, выбор наиболее вероятного токена) у последнего чекпоинта.
- Оценка: средняя точность C минус C-shuf по 8 seed, 95% доверительный интервал (ДИ) Уэлча по точностям отдельных прогонов.
- Решение, по порядку: (1) ДИ целиком в пределах 3 процентных пунктов от нуля - эффект практически мал; (2) нижняя граница строго больше 0 - информация помогает; (3) верхняя граница строго меньше 0 - вредит; (4) иначе «не определено», в отчёте приводится граница эффекта.
- Заранее выбран порог практически малого эффекта в 3 п.п.
- Упавший прогон перезапускается с тем же seed; все завершившиеся прогоны входят в выборку.

Вторичные сравнения и метрики:

- C минус A и C-shuf минус A тем же методом.
- Кривая строгой точности на val по чекпоинтам.
- Классы исходов на test: верно / «почти» (числа верные, значение нет) / неверные числа (повтор, пропуск, лишнее) / нет тега или не разбирается / деление на 0. Для B - доля взломов (награда 1 при нестрогой проверке, неверно при строгой).
- По шагам во всех условиях: доля групп, где все 8 ответов строго неверны.
- Средняя длина ответа, KL к исходной модели, обучающая награда.

Ограничения контроля (измерить и обсудить в отчёте):

- Сохранение исходных оценок: при 0 или 1 ответе «числа верные, значение нет» перестановка не меняет награды. Считается доля таких ответов.
- Шум: перестановка нарушает связь награды с близостью и добавляет случайность. Разность C и C-shuf отражает пользу информации вместе с потерями от шума.

## 2. Данные и модель

- Задачи. Генератор строит случайное дерево выражения над всеми n числами, используя сложение, вычитание, умножение и деление. Цель - его целое положительное значение в заданном диапазоне. Цели, равные одному из чисел или их сумме, отбрасываются. Дубликаты удаляются по ключу `(отсортированные числа, цель)`. Каждая задача принадлежит одному срезу: calib 300 (калибровка), train 5000, val 200 (кривые), test 2000 (итог). Seed данных 0; jsonl и `data/SHA256SUMS` в репозитории.
- Сложность калибровалась на calib (300 задач, greedy, CPU). 4 числа из 1-25: база решает 0/64, в 95% ответов набор чисел неверный (модель берёт 3 числа по образцу примера). 3 числа из 1-25, цель 10-100: 11.3% (near 48%, wrong_numbers 41%). Выбран этот вариант: точность находится в диапазоне задания 10-50%, а частые группы с нулевой точностью позволяют проверить гипотезу. Для чисел 1-15 получена 3771 уникальная задача при запланированных 7500. Подсказка «think briefly» при `enable_thinking=False` дала ту же точность.
- Модель. Qwen3-0.6B (instruct), `enable_thinking=False`, `max_completion_length=256`. Промпт (правила, формат `<answer>`, один пример) одинаков при обучении и оценке всех условий.
- Проверка (`countdown.py`): последний `<answer>...</answer>`; `ast` в режиме выражения, допустимы `BinOp` с `Add/Sub/Mult/Div`, целые `Constant` и скобки; мультимножество чисел равно исходному; вычисление в `Fraction`; деление на 0 даёт неверный ответ.
- Проверка тестами (`test_countdown.py`): верный ответ; повтор числа; пропуск; в теге только цель; `= 46`; несколько тегов; деление на 0; `1/3*3`; склейка `37`; унарный минус; C-shuf сохраняет мультимножество наград группы; задачи решаемы и срезы не пересекаются.

## 3. Обучение

- `trl.GRPOTrainer` 1.16.0, vllm 0.31.0 (поддерживается trl 1.16.0), torch 2.13.0; серверный `pip freeze` в `requirements.txt`.
- LoRA `r=32` на всех линейных слоях, lr 1e-5 с линейным снижением, одинаково для всех условий.
- Конфигурация: один процесс; `num_generations=8`; `num_iterations=1`, одна генерация на шаг оптимизатора (ответы выдаёт текущая модель); `scale_rewards="group"`; `loss_type="dapo"` (по умолчанию в trl 1.16.0); `beta=0.01` во всех условиях; исходная модель с выключенным адаптером служит референсом для LoRA; vLLM colocate; temperature 1.0.
- C-shuf: группировка по промпту с assert на непрерывные блоки по 8.
- Функция награды пишет каждый оценённый ответ (шаг, задача, строгий исход, значение, награда, текст) в `completions.jsonl`. Из него считаются строгая точность при обучении, доля групп без верных ответов и сохранение оценок после перестановки.
- Бюджет одинаков: фиксированное число шагов, по 32 задачи на шаг и 8 ответов на задачу. Число шагов выбирается по пилоту, ориентир 45-60 мин на прогон. Чекпоинты LoRA каждые 25 шагов, итог - только последний.
- Генерация vLLM может различаться между запусками с одинаковым seed; разброс оценивается по seed.

## 4. Оценка

- `evaluate.py`: greedy (temperature 0, 256 токенов) через vLLM с подгрузкой LoRA; база и все чекпоинты на val сразу после каждого прогона, итоговые адаптеры и база на test.
- Все генерации сохраняются в jsonl, `analyze.py` строит графики и таблицы на CPU.
- Таблица до и после: ответы базы, A, C-shuf, C, B на 10 фиксированных задачах test (seed 0). Примеры ошибок каждого класса и взлома из B.
- Графики по шагам со средним и стандартным отклонением по seed: обучающая награда, строгая точность на обучении и val, KL, средняя длина, доля групп без верных ответов. Итоговая точность на test по условиям, доли классов исходов, ДИ разностей.

## 5. Что разобрать в анализе

- Если точность C и C-shuf близка и обе выше A, это согласуется с объяснением через оживление групп и бонус за числа. Здесь оценивается их совместный эффект; следующий шаг - фиксированный бонус за правильный набор чисел.
- Если C лучше C-shuf, проверить по классам исходов, связан ли выигрыш с исправлением неточных выражений или только с форматом.
- Сохранение оценок после перестановки и шум: как они влияют на вывод.
- Длина ответа как альтернативное объяснение.
- Эффект может проявляться рано и размываться к концу: смотреть кривую val.
- Вывод относится к нормировке `scale_rewards="group"`; влияние самой нормировки можно проверить отдельным сравнением.
- Ограничения: одна модель и размер, LoRA, от 5 до 8 seed, одна сложность; B - один seed.

## 6. Основная серия (зафиксировано 02.11.2026 до её запуска)

- После пилота выбран бюджет 300 шагов на прогон: `32 * 8 * 300 = 76800` ответов. Итоговая выборка охватывает основную серию.
- В пилоте 50 шагов обучения заняли 505.6 с для A и 455.4 с для C. Ожидаемое время внутри `trainer.train()` при выбранном бюджете - около 45-50 минут на прогон.
- Seed и число повторов прежние: A 0-4, C и C-shuf 0-7, B 0. Всего 22 прогона, последовательная очередь с чередованием условий по seed.
- Модель, данные, промпт, награды, lr, LoRA и лимит 256 токенов остаются как в пилоте. Обрезания длинных ответов считаются частью поведения при этом фиксированном лимите и обсуждаются как ограничение.
- Перед первым обучением база оценивается на val и test. После каждого прогона все чекпоинты оцениваются на val для кривых обучения; на test оценивается адаптер после 300 шагов.
